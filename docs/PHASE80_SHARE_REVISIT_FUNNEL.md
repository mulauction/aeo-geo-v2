# Phase 80 — Share Revisit/Conversion Funnel (DOCS ONLY)

## 목적
Share 이후 재방문/재열람/재분석 전환을 자연스럽게 강화

---

## 사용자 여정 정의 (4종)

### J1: OK 리포트 공유 (링크 복사 → 상대가 열람 → 재열람)
- Share(OK)에서 사용자는 “팀에 바로 공유”가 목적이라 `링크 복사(재열람 링크 복사)`를 사용한다.
- 공유된 링크를 받은 상대는 링크 클릭으로 Share 화면에 진입한다(환경/브라우저 정책은 기존 규칙 유지).
- 상대는 OK 리포트 요약을 읽고, 필요한 경우 PDF로 저장하거나 내부 공유를 진행한다(버튼/동작은 기존 유지).
- 원 작성자는 동일 링크로 다시 들어와 “같은 리포트”를 재열람한다(재방문).
- 재열람 시에도 “현재 화면의 의미/다음 행동”이 1~2줄 안내로 즉시 이해되어야 한다(강매 금지).
- 실패/오해 지점이 있으면 **버튼 추가 없이** 문구/배치(화면용)로만 보정한다.

### J2: OK 리포트 보관 (PDF 저장 → 사내 공유/보고)
- Share(OK)에서 사용자는 “문서 첨부/보고/보관”이 목적이라 `PDF로 내보내기`를 사용한다.
- 미리보기에서 저장/인쇄를 완료한다(Print SSOT는 불변; 동작/키워드/가드 변경 금지).
- 저장된 PDF는 사내 메신저/이메일/문서 결재 등에 첨부된다.
- 추후 재확인이 필요하면 원본 Share 링크(또는 재열람 링크 복사)를 통해 화면으로 재진입한다.
- 사용자는 “공유=링크, 보관=PDF”라는 선택 기준을 1줄 안내로 빠르게 떠올릴 수 있어야 한다.
- Print/PDF 관련 UX 개선은 반드시 **화면용 카피 범위**에서만 계획한다(SSOT/print CSS 불가침).

### J3: Non-OK 복구 (최근 리포트 열기/다시 분석 → OK 도달)
- Share(Non-OK: NO_REPORT/EXPIRED/OTHER_DEVICE/FETCH_FAIL/INVALID_ID 등)로 진입한 사용자는 “열리지 않음”을 먼저 이해해야 한다.
- 사용자는 안내에 따라 “복구” 행동을 선택한다: (1) 다시 분석, (2) 이 브라우저의 최근 리포트 열기.
- Non-OK 세부 상태에서도 **Phase 77 CTA 정책(버튼/순서/동작)은 그대로 유지**한다(불변).
- 사용자가 복구 후 OK에 도달하면, 다음 행동은 “공유/저장”으로 자연스럽게 전환된다.
- 복구 단계의 핵심은 “왜 안 열리는지” 장문 설명이 아니라, 1~2줄로 “다음 행동”만 명확히 하는 것이다.
- 복구 실패 시에도 버튼 추가/행동 변경 없이, 화면 안내(문구)로만 오해를 줄인다.

### J4: 개선 필요 시 (Pro는 보조 옵션): 개선 → 재분석 → OK
- Share(OK 또는 Non-OK)에서 사용자가 “개선이 필요”하다고 판단한다(측정/근거/WHY 참고).
- 사용자는 개선 작업(콘텐츠/구조/브랜딩/URL 등)을 진행한 뒤 다시 분석을 통해 최신 리포트를 생성한다.
- 재분석 후 OK에 도달하면, 링크 공유 또는 PDF 저장으로 결과를 정리한다.
- Pro/업그레이드는 “필요할 때만” 보조 옵션으로 언급한다(강매 금지; 신규 CTA 금지).
- 핵심 전환은 “개선 → 재분석 → OK”이며, Share 화면은 그 다음 행동(공유/저장)을 안내한다.
- UI-only 단계에서는 **버튼 추가 없이** 카피로만 “다음 행동”을 정돈한다.

## 상태 매핑 테이블 (의도/다음 행동/혼란/가이드 원칙)

| 상태 | Primary intent | Top 1~2 next actions | Common confusion | One-line guidance principle |
|---|---|---|---|---|
| OK | 결과를 공유/보관/재열람 | (1) 링크 복사 (2) PDF 저장 | “무엇을 하면 좋은지”가 불명확하거나, 링크/PDF 차이를 모름 | 공유=링크, 보관=PDF를 1줄로 제시 |
| Non-OK (공통) | 복구해서 리포트를 보게 만들기 | (1) 다시 분석 (2) 최근 리포트 열기 | “왜 안 열리나?”, “내 리포트가 사라졌나?” | 원인 장문 대신 복구 옵션만 1줄로 제시 |

> Non-OK 세부 상태(EXPIRED/OTHER_DEVICE/NO_REPORT/FETCH_FAIL/INVALID_ID 등)에서도 **Phase 77 CTA 정책(버튼/순서/동작)은 그대로 유지**한다.

## 실패 지점 & 가드레일 (불변 규칙 기반)

### 주요 실패 지점
- **Non-OK에서 사용자가 멈춤**: 원인을 길게 읽지 않거나, 무엇을 해야 할지 모르고 이탈.
- **OK에서 다음 행동 미선택**: 공유/저장/재열람 경로가 눈에 띄지 않아 행동 전환이 약함.
- **Print/SSOT 혼선**: 인쇄/저장 흐름이 상태별로 바뀌면 혼란과 회귀 위험이 커짐.
- **Telemetry가 방해 요소로 인지**: 선택 기능이어야 하며, 화면 진입/복구를 막으면 안 됨.

### 가드레일(반드시 유지)
- **Phase 77 CTA 정책 불변**: 신규 버튼 제안/CTA 재배치/동작 변경 요청 금지.
- **Print SSOT 불변**: print CSS/SSOT 키워드/가드/로직은 영향을 받으면 안 됨.
- **Telemetry는 optional**: 비필수이며 화면 진입/복구를 블로킹하면 안 됨.
- **UI-only 단계는 카피만**: 신규 버튼 없이, 1~2줄 안내(화면용)로만 개선.

## Phase 80-1 (UI-only) 계획 메모 (지금은 코드 변경 없음)

### 배치 원칙(화면용, Print/SSOT 영향 0)
- **Screen-only, no print CSS**: `<style>`/`@media print`/SSOT 키워드/가드 편집 금지.
- **CTA 충돌 금지**: Phase 77 CTA 영역과 경쟁하지 않도록, “안내 텍스트”로만 추가.
- **1~2줄**: 정보 안내용, 비세일즈(강매 금지), 명령형 최소화.

### 권장 위치(예시, 신규 UI 추가 금지)
- **OK**: 상단 헤더/요약 근처의 기존 안내 텍스트 영역에 1줄 보강
- **Non-OK**: Non-OK 안내박스 상단의 기존 안내 텍스트 영역에 1줄 보강

### 마이크로 카피 후보 (KR, 1~2줄)

#### OK — 재방문/공유/보관
- “팀 공유는 링크 복사, 내부 보고는 PDF 저장이 편합니다.”
- “공유는 링크 복사, 보관은 PDF 저장을 사용해보세요.”
- “필요하면 링크를 복사해 공유하거나 PDF로 저장해 두세요.”

#### Non-OK — 복구
- “이 링크는 이 브라우저에 리포트가 없습니다 → 최근 리포트 열기 / 다시 분석”
- “리포트를 열 수 없습니다 → 최근 리포트 열기 또는 다시 분석하세요”
- “복구 방법: 다시 분석 또는 최근 리포트 열기(이 브라우저)”

## 문서 자체 점검(Phase 80-0)
- 신규 버튼/CTA 재배치/동작 변경을 요구하지 않는다.
- Print/SSOT/telemetry/state/schema에 영향이 없도록 “화면용 카피”만 다룬다.
